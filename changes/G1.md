# G1: A failed save is never silent (WEB-010)

## Built
- One shared way to handle a failed write, `apps/web/src/ui/writes.ts`: `attempt(what, run)` for
  one-click writes (a toast says what didn't happen and why, with Retry when trying again could
  help: no answer, 5xx, 408, 429; never for a 4xx refusal), `useWrite()` for forms and inline
  edits (busy, the sentence to show, busy always ends, the fields are never touched),
  `failureText(e, what)` (what didn't happen, then the server's reason as a sentence, or what to
  do; 403 = "You can read this but not change it."; never exception text). (commit 00a6c97)
- The net: `api()` remembers every error that came from a write (anything but GET, never a
  cancel; `isFailedWrite`), and `installWriteNet()` (main.tsx) says any such error nobody caught in
  a toast instead of only the console. A call site added later that forgets is still not silent.
  (commit 00a6c97)
- `Confirm` awaits an async `onConfirm`: the dialog stays, its button waits, and a failure is said
  inside it (`failed:` says what didn't happen); confirming again is the retry. A plain action
  still closes at once. (commit 233978a)
- Every call site that could fail silently now goes through the helper (list below), the three
  loaders the ticket names show an error with Retry, and a lint rule
  (`basalt/async-handler-catches`, apps/web/eslint.config.js) refuses an async `on…=` handler on a
  DOM element or a pass-through control (Button, Input, Form…) that awaits outside a try/catch.
  (commit 0b2a5c9)

Fine as they are, on purpose:
- `signOut()` swallows a failed `POST /api/auth/logout`: forgetting the token locally is still right.
- Settings → Device's `POST /api/auth/unlock/options` and Settings.tsx's summary call: reads made
  with POST; a failure leaves the summary blank.
- noteSync's `keepalive` PUT on the way out: nothing is left on screen to tell, and the draft
  mirror (`basalt-draft:<id>`) offers the text back on the next open (R7).
- Capture: after a failure the text stays with the reason under it; Esc or Cancel after that is
  the person choosing to drop it.

## Changelog lines (user-facing, for [Unreleased] → Fixed)
- A change that doesn't save is never silent: a toast says what didn't happen and why, with
  Retry when the server didn't answer; forms keep what you typed and their button comes back.
- Confirm dialogs (delete a document, remove a project from the board) stay open and say why
  when the server refuses, instead of closing as if it had worked.
- Mail no longer says "isn't connected" when the server didn't answer; it says so, with Retry.
- The project note on a project page says it didn't open, with Retry, instead of "Opening the
  note…" for ever.
- Planning's new-event popover keeps its title when the event didn't save.
- Sending a staged draft whose clean-up fails says the draft is still listed, so it isn't sent
  twice.

## CLAUDE.md changes to apply (exact text, and where)
- "Conventions & gotchas", after the "Typing is never lost" bullet, add:
  - **A failed write is never silent** (`apps/web/src/ui/writes.ts`, audit WEB-010): a
    one-click write goes through `attempt(what, run)` (a toast with the reason, and Retry when
    the server didn't answer), a form through `useWrite()` (the reason beside it, busy always
    ends, nothing typed is cleared), and a Confirm's `onConfirm` may return the write's promise
    (the dialog waits and says why it failed). `api()` remembers failed writes and
    `installWriteNet` (main.tsx) says any nobody caught. ESLint's `basalt/async-handler-catches`
    refuses an async `on…=` handler that awaits outside a try/catch. The message is the page's,
    never Orr's: what didn't happen, then why ("The step wasn't ticked. The server didn't answer.").
- "Design rules", "One of each pattern", after "use `Confirm`, `Dialog` or `NameDialog`." add:
  "A failed change is said with `ui/writes.ts`, never `console.error` or nothing."
