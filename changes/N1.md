# N1: more than one mail account, and a note from an email in one click

Wave N, Jules's asks of 10 Nov: "connect more than one email account (my other addresses)" and
"make a note from an email in one click". Branch `waveN/N1-mail` from `9a74eb3`.

## Built
- Schema 7 and the server for several accounts: list, add, rename, default, order, remove; one
  inbox across them with `?account=`; message, send and drafts by account; Orr's and the MCP
  `list_email` / `read_email` / `draft_email` take an account and say it (6a2902f)

  `VaultStore.write`; a second click opens it; toast with Open, Undo and the offered project
  (4f824c9)
- What the browser pass found: notes address without `.md`, no heading or relative link in the
  note, chips for one-at-a-time, wraps and tooltips (1b81704)

## The schema 7 migration
`mail_accounts.user_id` was `UNIQUE`; SQLite can't drop a column's UNIQUE, so `mailAccountsMany`
(apps/server/src/db.ts) makes the table again without it, in one transaction, and copies every row
column by column (`password_encrypted` unchanged), each old row becoming its person's default
(`is_default = 1`). It runs only while the unique index on `user_id` is there, after the usual copy
to `<data>/backups/basalt-schema-6-<date>.db` and after `addColumns` (`label`, `position`,
`is_default`, `mail_drafts.account_id`). Checked: `schema-upgrade.test.ts` (a schema 6 table typed
in verbatim, rows compared byte for byte; sabotage: no rebuild, rows not default, password column
swapped, all red) and a schema 6 database seeded by main 9a74eb3 with an account row added: the
row's hash is the same before and after, it is the default, the copy was made.
**Integrator: before shipping, the live DB goes 6 → 7.** An older build refuses a schema 7 DB
(as designed); the pre-upgrade copy is the way back.

## Decisions
- Inbox: Jules, 24 Nov, "Both available at choice (settings)". Settings → Connections → "How Mail
  shows your accounts" (this device, `orrama-mail-inbox`): One list for all accounts (default) /
  One account at a time. The filter is kept per device too (`orrama-mail-account`), like Mail's tab.
- Note folder: Jules, 24 Nov, `Personal/<you>/` (recommended), beside quick capture's Inbox.
- A message's address: `/mail/<uid>` for the default account (so every old link and a one-account
  Mail read as before), `/mail/<account id without mail->.<uid>` for another.
- Default: an explicit `is_default`, else the first; removing the default promotes the next.
  Reconnecting an address already there (any case) gives it the new password, not a second row.
- An account is named by id, address or label (`accountByRef`); an unknown name is refused with
  the names there are, never answered from another account.
- Drafts of a removed account stay, `account_id` cleared: they go from the default, and the
  card says "From <default>".
- `DELETE /api/mail/account` still removes every account (old meaning, Settings' one-account
  Disconnect); `DELETE /api/mail/accounts/:id` removes one. `GET /api/mail/account` keeps its
  shape (the default) plus `accounts` (a count) for Today and a person's page.
- An account that can't be read is reported (`accounts[].failed`, "Couldn't reach Work.") and the
  others still show; only all failing is a 502.
- The note: front matter `title`, `tags: [mail]`, `domain: personal` (store adds `id`), `from`,
  `date`, `message-id` (Message-ID, else `uid:<uid>@<address>`: the dedupe key), `mail`
  (`/mail/…`). Body: From with the sender's `[[path|name]]` when a `#contact` note has the
  address, when, the text as the Reader shows it (core `mailText.ts`, now shared), attachments by
  name. **Mail text is escaped** (`mailSafe`): no `#tag`, `[[link]]`, `- [ ]` step or `# heading`
  from a mail reaches the vault (anyone can send mail). No `# title` (Notes shows the title) and no
  link to the message in the body (the editor draws only wiki links; in Obsidian a relative link
  opens or makes a note): the reference is the front matter's `mail`.
- Project offered, never decided: a project tag in the sender's contact note's front matter, or
  on a note made from an earlier mail of the thread (`References`). The toast offers the first.
- No keyboard shortcut: the Reader has no key pattern.
