## Decisions (Jules, 24 Nov, by the question tool; each the recommended option)
- "Make a project…" **replaces** "Make this a project" (the note-becomes-the-project promote). `POST /api/projects/promote` stays (tests and any other caller).
- No "Bring the note's N tasks" switch: the dialog says "Its N open tasks will count for the project." The tag is what makes them count; nothing is ever copied.
- A note that brings open tasks gets no "- [ ] First step" placeholder: `projectNoteScaffold`/`createProject` take `firstStep: false`. This is the one change inside the create path (brief: "say so"); every other caller is unchanged.

## Other choices made here
- Undo is three existing writes in this order: move the note back (if moved), `POST /api/projects/:slug/trash` (deletes the project, takes the tag off), `POST /api/projects/<old>/notes` (if the note left another project). The order matters: the delete trashes whatever is in the project's folder. The project note ends up in `.trash/` like any deleted project. Verified byte-identical note on scratch and in `project-from-note.test.ts`.
- A second ask on a note already in a project is a 409 unless `anyway: true`; that also stops a double click making two projects.
- "Already in <project>" in the palette opens the project; "Make a new project anyway" is only in the ⋯ menu (brief).
- Life area: the note's own area (tree `category`), else the catch-all, so the select always shows what is sent.
- The "Next three weeks" bug was not the expansion (`/api/events` already expands series, ICS reader) but `nextWeeks` dropping any title seen three times. Fixed by reducing each series to its first day in the span; hand-typed repeated one-offs are still left out as before.
- Month-note name is display-only and Recent/Pinned/Find only: the tree's folders keep "2026-11" so the months sort in order (changing core `displayTitle` would have sorted them April, August…).
- Find gets page actions through a tiny registry, `ui/pageActions.ts` (`usePageActions` while on screen). Usable by other pages later.
