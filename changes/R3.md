## Board vs app: differences left on purpose

- **The gathered vault is real.** The prototype's slices are fixed made-up weights; the app's are
  the signed-in vault's life areas by note count (with an extra grey slice for notes in none),
  projects as the orange inner dots and people in the middle band. If the server hasn't said the
  shape within 500 ms the dots close into the halo uncoloured rather than in invented slices.
- **The lock's desktop keypad.** The board's desktop lock shows Touch ID. A computer with no Touch
  ID enrolled (or a WebKit window that reports none) gets the phone's keypad instead, because the
  passcode is its only quick way in; typed digits work with or without it. On the scratch server
  (no enrolled device) that is what shows.
- **The lock's password is in place**, signing in as the remembered account, as on the board.
  Before, "Use password instead" went to the full sign-in (any email). An account with no passcode
  and no Touch ID now goes straight to the full sign-in, so a stale remembered address can never
  strand anyone at a lock.
- **Passcode length.** The prototype shows six pins; the app's passcode is four digits
  (`passcodeSchema`), so four.
- **First run's line** says "I found 234 notes." without "in Notes": the app doesn't know the
  folder's name. An empty folder says "No notes here yet." and offers only Start with today.
- **First run asks all three fields** (name, email, password) as the board does; before, the name
  was optional and there was a confirm-password field, which the board replaces with Show.
- **Boot** has no board. Built from §2.14/§5: the head (HeadMark) rising 600 ms from behind a
  hairline horizon on the ground; on a local server it is usually replaced before it has risen.
- The prototype's "(prototype)" replay links are not built.
