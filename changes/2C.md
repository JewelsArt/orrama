## What a new person sees now (the app)
Open Orrama → "Welcome to Orrama" (name, email, password) → "Where are your notes?" (an example,
start empty, or "Use notes I already have" → **Choose the folder…**, the Mac's/Windows' own chooser,
then what it holds in words) → **"How should Orr think?"**: Sign in with ChatGPT (OpenAI's page opens
in their browser; the app says "Finish signing in in your browser, then come back here." and moves on
by itself when it lands), Use a key (Anthropic or Google, two lines on where to get one with the link,
the model filled in, the key checked before it's saved), or Later ("Orr stays off, and nothing is
sent anywhere.") → the dots count and gather → Today. Forgot the password later: the sign-in's
"Forgot your password?" opens "Choose a new password" right there; every other device is signed
out, the notes, mail and Orr's settings stay.

## How the pieces fit (for the integrator and CLAUDE.md)
- **The mark**: the shell's initialization script sets `window.__ORRAMA_DESKTOP__ = { shell: 1 }` on
  every page of its window; `apps/web/src/desktop.ts` (`inApp`) is the one reader. Jules's older
  `dev.basalt.app` window has no mark, so it keeps the browser's ways (typed path, ChatGPT in the same
  window, reset said in words): nothing breaks for him before 2H.
- **The folder chooser**: `desktop.ts` `pickFolder` → `__TAURI_INTERNALS__.invoke("plugin:dialog|open",
  { options: { directory: true, … } })`. No npm package added (the call is the plugin's one command).
  If the call fails the chooser hands over to the typed field.
- **The capability** (`capability.rs`): made at run time, once the server answers, per port:
  `{ identifier: server-page-<port>, local: false, windows: ["main"], remote: { urls:
  ["http://localhost:<port>"] }, permissions: ["dialog:allow-open"] }`. No `capabilities/` folder.
- **The reset**: Login's link (in the app, and `resetHere`) → `location.assign("/_shell/reset")` →
  window.rs `Route::Do(Action::Reset)` (only on our server's port) → reset.rs POSTs
  `/api/auth/reset/ticket` with `X-Orrama-Shell-Token` → the window opens `/reset#ticket=<t>` (or
  `#failed`) → App reads it once at load (`takeResetTicket`), tidies the address → `door/Reset.tsx`.
  A ticket: 32 random bytes, base64url, 10 minutes, only the newest, spent before the hash is
  awaited; a wrong email keeps it. The reset is `revokeEverything` (sessions, API tokens, Touch ID,
  passcode, feed link) then a new session for this window.
- **ChatGPT**: in the app, `start { wait: true }` (no return address), `location.assign(url)` (the
  shell sends it to the system browser), poll `GET /api/admin/ai` every 2 s and on window focus,
  10 minutes. **In a plain browser tab the old same-window flow stays**, on purpose: it already works
  there, needs no second tab (Safari blocks one opened after an await), and comes back where it
  left; at first run in a browser it comes back to Settings → Orr & AI, signed in, past the gather.
- **Sign in with ChatGPT is offered to everyone** (the "Other people use a key" comment in
  `chatgpt.ts` is gone). It rests on the source being public by the friends' release (2G):
  OpenAI's terms cover open-source and personal local projects; until the repository is public it
  covers only Jules's own copy.
- **The notes folder before a choice** (packaged only): `vaultDir()` = `ORRAMA_VAULT_DIR` ?? stored ??
  (packaged ? `<data>/notes-not-chosen` : own). `storeNotesFolder` keeps the own folder in the file
  when packaged; a chosen own folder deleted since is made again. `POST /api/settings/start` is 409
  while the stand-in is read.
