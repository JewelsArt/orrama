## What needs Windows, and how to prove it
After the Actions reset, once this is on `main`:
1. `gh workflow run windows.yml --ref main`: the server suite on Node 24 on `windows-latest`,
   including `packaged-stop.test.ts` (the stdin stop is the only graceful stop a Windows child
   has). Green = the run passes as on 22 Oct; `bundle.test.ts` says "skipped" there.
2. 2D's job (or a step added to `windows.yml`) builds and runs the bundle on the runner:
   `pnpm --dir apps/web build`, `pnpm --dir apps/desktop prepare-bundle`,
   `pnpm --dir apps/server exec vitest run test/bundle.test.ts test/packaged-stop.test.ts`.
   Green = 3 + 3 tests passed, no skip. That proves node.exe, the PE addons, the worker and
   the stdin stop (no WAL left) on Windows.
3. By hand on a PC or the UTM VM (D9): copy `binaries/node-x86_64-pc-windows-msvc.exe` and
   `resources/server/` (cross-built here), then in PowerShell
   `Get-AuthenticodeSignature .\node-x86_64-pc-windows-msvc.exe` (Status `Valid`, OpenJS
   Foundation) and
   `$env:ORRAMA_PACKAGED=1; $env:ORRAMA_DATA_DIR="$env:TEMP\o\data"; $env:ORRAMA_DEFAULT_NOTES_DIR="$env:TEMP\o\notes"; $env:ORRAMA_ALLOW_DEV_SECRETS=1; $env:PORT=4870; .\node-x86_64-pc-windows-msvc.exe .\server\server.mjs`
   then open http://localhost:4870, sign up, Start empty; type `stop` and Enter in that window: it says "stop: closing", exits, and `$env:TEMP\o\data` holds no `basalt.db-wal`.
Only checked on macOS: `chmod` on the log and export (Windows sets nothing but read-only;
`%LOCALAPPDATA%` is per-user anyway), the "Type the whole path, starting with / or ~/." hint
(a `C:\…` path is accepted, the words say `/`), paths with `\`.
