# S02 — Security: close the no-password takeover paths

## Fixed
- SEC-001 — quick-unlock spends an attempt in one `UPDATE … RETURNING` before Argon2 runs; a burst checks 5 codes, then the cooldown, 10 in all, then only the password works (commit fb98ebd)
- SEC-003 — the login throttle counts an attempt before the verify (`LoginLimiter.attempt`); 20 wrong passwords at once → 5 × 401, 15 × 429, 5 hashes (commit fb98ebd)
- SEC-011 — sign-up refuses a missing/used/expired invite before hashing, and is throttled per address (commit fb98ebd)
- SEC-005 — every request must be addressed to loopback or a host in `BASALT_PUBLIC_ORIGINS` (any port), else 421 before any route, static file or WebSocket upgrade (Jules's choice, 11 Oct) (commit 0eeca65)
- SEC-013 — one central gate: a route with `config: sessionOnly(reason)` refuses `bslt_` tokens in `authenticate`; applied to every credential route (passcode, Touch ID, sessions, tokens, webhooks, mail send/account, ICS feed token, all of `/api/admin/*`, revoke-all) (Jules's choice: the full set, 11 Oct) (commit 0fd0213)
- SEC-004 — AI settings are session-only, and a blank key is refused when the openai-compatible base URL changes (commit 0fd0213)
- SEC-014 — the mail account is session-only, IMAP/SMTP hosts must be public or in `BASALT_FETCH_ALLOW`, and failures are a fixed sentence (detail in the log) (commit 0fd0213)
- AI-013, OPS-009 — boot writes nothing into the vault; the MCP README registers Basalt with `claude mcp add --scope user` so the token lives in `~/.claude.json` (Jules's choice, 11 Oct) (commit b4c88cd)
- SEC-006 — `rotate-secret-key` re-encrypts `meta.chatgpt_credentials`; the work is an exported, tested `rotateSecrets()` (commit 701ba1c)
- SEC-007 — a password change (`account.ts`) and the new Settings → Signed in → "Sign out everywhere" end every session, API token and Touch ID device and clear the passcode and the calendar feed link (`revokeEverything`, `POST /api/auth/revoke-all`) (commit 8c7a69d)
- SEC-008 — Touch ID login/options answers every address alike (200, no stored credential ids); an unknown address's password sign-in runs Argon2 against a dummy hash (commit 1fbc8ee)
- SEC-009 — expired WebAuthn challenges are deleted on the next one, and live ones are capped at 200, oldest evicted first (commit 1fbc8ee)
- SEC-010 — live-sync frames are capped at 16 KiB; a bigger one is closed (1009) on its header, before it is read or parsed (commit b048c33)
- REG-002 — the boot guard refuses an empty or < 32-character secret, naming it; `envProblems` reports "set but empty" (commit c7cb368)
- SEC-015 — webhook signing secrets are encrypted at rest, sealed once at boot for existing rows, and rotated by `rotate-secret-key`; **SCHEMA_VERSION 2 → 3** (the last commit on the branch, which also carries this file)

## Changelog lines (user-facing, for [Unreleased] → Fixed / Security / Internal)
- Security: the 4-digit quick-unlock passcode can no longer be brute-forced by sending many guesses at once; at most ten are ever checked before the password is required.
- Security: sending many sign-in or sign-up attempts at once no longer slips past the "five wrong passwords, then wait" limit, and a refused attempt no longer costs a password hash. Sign-up is rate-limited too.
- Security: Basalt only answers requests addressed to `localhost`, `127.0.0.1`, `[::1]` or a host in `BASALT_PUBLIC_ORIGINS`, so a web page you visit cannot reach it by re-pointing its own name at your machine (DNS rebinding).
- Security: an API token can no longer turn itself into a full session or manage credentials. It is refused on passcode, Touch ID, sessions, tokens, webhooks, mail sending and the mail account, the calendar feed link, and all workspace/AI settings.
- Security: changing the openai-compatible base URL in Settings → AI now needs the API key typed again, so the stored key cannot be redirected to another server.
- Security: the mail account's IMAP/SMTP server must be a public address (or listed in `BASALT_FETCH_ALLOW`), and a failed connection no longer reports the remote error text.
- Security: changing your password signs you out everywhere — every session, API token and Touch ID device — and clears the passcode and the calendar feed link. Settings → Signed in has a new "Sign out everywhere" that does the same.
- Security: the Touch ID sign-in no longer reveals which email addresses have an account or a passkey, and the password sign-in takes as long for an unknown address as for a wrong password.
- Security: webhook signing secrets are now stored encrypted, like the other credentials.
- Fixed: the server refuses to start when `BASALT_SECRET_KEY` or `BASALT_JWT_SECRET` is set but empty (it used to start and encrypt credentials under an empty key).
- Fixed: `rotate-secret-key` now also re-encrypts the Sign in with ChatGPT credentials and webhook secrets, so rotating the key no longer quietly signs you out of your ChatGPT plan.
- Fixed: Basalt no longer creates `.mcp.json` and `CLAUDE.md` in your vault on every start. Register the MCP server with `claude mcp add` instead (see `apps/mcp/README.md`); an old placeholder `.mcp.json` in the vault can be deleted.
- Internal: unauthenticated Touch ID challenges are cleaned up and capped; live-sync frames are capped at 16 KiB.
- Upgrading: the first start of this version encrypts every stored webhook secret and stamps the database as schema 3; an older build will then refuse to open it, so take a database backup before shipping. Reaching Basalt by a bare LAN or tailnet IP now needs that address in `BASALT_PUBLIC_ORIGINS`. A Touch ID passkey created as non-discoverable (unlikely on macOS) needs enrolling again.

## CLAUDE.md changes to apply (exact text, and where)
- "Start here", the secrets bullet: replace `Changing \`BASALT_SECRET_KEY\` orphans the stored mail password and AI key — run` with:

  > Changing `BASALT_SECRET_KEY` orphans every stored credential (mail password, AI key, ChatGPT sign-in, webhook secrets, calendar feed URLs) — run

  and replace `The server refuses to boot on the shipped placeholders regardless of \`NODE_ENV\`;` with:

  > The server refuses to boot on the shipped placeholders, or on a secret that is empty or under 32 characters, regardless of `NODE_ENV`;

- "One shared vault with Obsidian", after the **First index stamps every note** paragraph, add:

  > **Nothing else is written into the vault at boot.** Basalt used to create a `.mcp.json` (a slot for an API token, in the folder Obsidian Sync, iCloud or git copies elsewhere) and a `CLAUDE.md` whenever they were missing. The MCP server is registered with `claude mcp add --scope user`, which keeps the token in `~/.claude.json` (`apps/mcp/README.md`); a vault `CLAUDE.md` is the user's own file. `test/vault-untouched.test.ts` boots against a vault and compares every byte.

- "The agent can draft mail, never send it": replace `\`POST /api/mail/send\` refuses API\ntokens outright` with:

  > `POST /api/mail/send` is session-only (see **API tokens are the weaker credential**)

- "Live sync", at the end of the paragraph, add:

  > Frames from a client are capped at 16 KiB (`WS_MAX_FRAME`, `main.ts`): a client only sends its auth frame and presence pings, and the first frame is parsed before it is known to be a valid auth.

- "Conventions & gotchas", replace the **Touch ID trusts only known origins** bullet with:

  > - **The server answers only to its own names.** Every request — API, static files, the WebSocket upgrade — must carry a `Host` of `localhost`, `127.0.0.1`, `[::1]` or a host in `BASALT_PUBLIC_ORIGINS` (any port), or it gets a 421 before any route runs (`allowedHost`, `main.ts`). CORS cannot stop DNS rebinding: a page that re-points its own name at 127.0.0.1 is same-origin, but its browser still sends its own name as `Host`. So set `BASALT_PUBLIC_ORIGINS` (comma-separated, e.g. `http://localhost:4623,https://<mac>.<tailnet>.ts.net`) in the launchd plist for every name Basalt is reached by — a bare LAN or tailnet IP included. Touch ID trusts only those origins too; unset, the `Origin` must equal the address the request was sent to.

- "Conventions & gotchas", replace the **Sign-in is throttled** bullet with:

  > - **Attempts are counted before they are checked.** Five wrong passwords from one address inside 15 minutes → 429 until the oldest ages out, even for the right password (`loginLimit.ts`, in memory). `LoginLimiter.attempt` checks and counts in one synchronous call BEFORE Argon2 — the old "check, await the hash, record the failure" let a burst sent at once all through. Sign-up has its own limiter and refuses a bad invite before hashing. The passcode spends an attempt in one `UPDATE … RETURNING` (5 then a minute's cooldown, 10 then password only). An unknown address is verified against a dummy hash, so timing does not say who has an account. Anything new that checks a secret counts first, then verifies.

- "Conventions & gotchas", after the **A session is a row** bullet, add:

  > - **API tokens are the weaker credential.** A `bslt_` token may read and write what its owner can and stage mail drafts — what the MCP server does — but never create, change or reveal a credential, or decide where one is sent. A route says so in its config, `{ preHandler: [app.authenticate], config: sessionOnly("why") }` (`routes/auth.ts`), and `authenticate` refuses the token with that reason. Today: passcode, Touch ID, logout and sessions, revoke-all, tokens, webhooks, mail send and mail account, the ICS feed token, all of `/api/admin/*`. `test/token-gate.test.ts` lists them; a new credential route opts in and gets a row there. A password change and Settings → Sign out everywhere end every session, token and Touch ID device and clear the passcode and feed link (`revokeEverything`, `sessions.ts`).

- "Conventions & gotchas", in the **Outbound requests to user-typed URLs go through `safeFetch`** bullet, after `Anything new that fetches a URL a user supplied uses it too.` add:

  > A connection `safeFetch` cannot make itself (IMAP/SMTP to a user-typed mail server) checks the host with `assertPermittedHost` first — same rule and allow-list, checked before connecting rather than in the socket.

## Not fixed (and why) / needs Jules
- WEB-013 (the 30-day session token in `localStorage`) — left for later, Jules's choice (11 Oct): it touches every request, the live-sync socket and the desktop app, and R0 is rewriting `App.tsx`. Plan, for its own session after R0 lands:
  1. Interim, no behaviour change: one accessor in `api.ts` for the auth header; `AskPanel.tsx` (builds its own header, and bypasses `api()`'s 401 → session-ended) and `App.tsx`'s `connectWs(localStorage…)` use it.
  2. `signIn` (routes/auth.ts) sets `basalt_session`: HttpOnly, SameSite=Strict, Path=/, Max-Age 30 days, Secure when the request came over https (the Tailscale name). Login/unlock/register/Touch ID responses stop returning the JWT; logout and revoke-all clear the cookie.
  3. `authenticate`: `Bearer bslt_…` stays the API-token path; a session is read from the cookie only (drop `Bearer <jwt>` after one release that accepts both, so open desktop windows don't all sign out at once).
  4. CSRF: SameSite=Strict + the Host allowlist (SEC-005) + require `Origin` to be one of `BASALT_PUBLIC_ORIGINS`/the request's own address on state-changing methods.
  5. Live sync: authenticate on the upgrade from the cookie; the first-frame auth goes away (and with it the pre-auth parse SEC-010 bounded).
  6. Check in WebKit (`scripts/webkit-snap.swift`) and in the Tauri window (same-origin `http://localhost:4623`), the vite proxy (:4625), and Touch ID unlock; tests: no session in the body or Web Storage, cookie flags, WS cookie auth, a cross-origin POST refused.
- SEC-008, partly: `POST /api/auth/unlock/options` still tells a caller who knows the address whether a passcode and a passkey are enrolled (unknown addresses get false/false). The lock screen needs it to show the right buttons; hiding it means a UI that offers both and fails quietly. With SEC-001 and SEC-005 fixed, this is low.
- SEC-008, not verified on a device: Touch ID sign-in now sends no `allowCredentials`, which relies on the passkey being discoverable (Safari/iCloud Keychain and Chrome's Mac authenticator make discoverable ones; enrolment asks for one). The browser pane has no authenticator; worth one real Touch ID unlock after shipping.
- SEC-014, residual: the mail host is checked before the IMAP/SMTP client connects, so a name re-pointed between the check and the connect is not caught (imapflow/nodemailer would need a custom `lookup`). `GET /api/mail/inbox` and `/message` still return the IMAP error text for the stored account (same class as SEC-014's error text; only reachable for an account a session connected).
- SEC-004: the AI base URL is not limited to public addresses — a local Ollama/LM Studio endpoint is a real use; the session gate and the re-enter-the-key rule protect the key.
- SEC-001: no separate per-address limit on unlock; the per-account counter (10 checks between password sign-ins) is the stronger bound.
- SEC-007: a live-sync socket already open when `account.ts` runs (a separate process) stays open until it reconnects or the server restarts; the tool says so.
- Docs not in my files: INSTALL.md should say that a Docker/LAN install reached by an IP or another name must list it in `BASALT_PUBLIC_ORIGINS` (SEC-005), and that `account.ts` now signs out everywhere.
- Test noise seen, not caused here: `new-folder-watch.test.ts` timed out twice in full runs (passes alone, on this branch and on the base), and the watcher tests hit EMFILE while several sessions' dev servers ran; documented in the commit messages.
