## Decided in this session (the prompt said: decide and say)
- **A new project's status is `planned`**, not `on-track`: nothing has started when a project is made; the header's status menu moves it on.
- **Switching the folder on a live server restarts the server in place** (main.ts): `VaultStore`'s root is fixed when it is made, and the calendar index, the webhooks, the live-sync bus and every route hold that store, so reopening it in place would mean resetting each of them. `buildServer({ restart })`; the entry point closes the build and makes a new one in the same process (same PID; the log says "restarting to read the notes folder chosen in the app" and "reading <folder>"). The page says "Orrama restarts to read that folder…" and waits until `/api/settings/server` names the new folder. Under launchd or the stage 2 sidecar nothing else is needed; a restart that fails exits, and the supervisor starts it again.
- **The ontology note's path: `Orrama/What things are.md`.** One quiet folder of Orrama's own (1D could put the life-areas note there too). Its text is core `ONTOLOGY_TEMPLATE` with four swaps (`starterOntology`, firstRun.ts, which throws if the template drifts): the title, the intro, `person | tag:contact, folder:Contacts | someone you know` (was `folder:01-Me/Contacts`, "someone Jules knows"), and the conversation type kept as "a saved conversation with an AI". `folder:` matches one folder only, so `Contacts/Companies/` notes are never read as people.
- **When the ontology note is written:** at the first-run choice (`POST /api/settings/start`), into the folder then read, and only when no note there is tagged `vault-ontology`; never at boot, never at sign-up (an invited second account writes nothing). Also when Settings → Change… settles another folder, so a friend's own notes folder gets one too; the chooser says so before they choose.
- **The password change keeps this device signed in** and ends every other session, API token and Touch ID device, and clears the passcode and the planning feed link (SEC-007's clean break, minus the session that just proved the password). `revokeEverything(…, keep)`.
- **Remove the example deletes for good** (no trash yet): the event, then exactly the notes it wrote (ids kept in `meta`, so a renamed one still goes), whatever was added to them. The Confirm says so. A calendar note it made stays if it holds rows of the person's own.
