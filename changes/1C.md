# 1C: Rename, move and delete notes

Stage 1, wave 1. Branch `stage1/1C-notes` from `sep-2026-redesign` (e1f7da2).

## Jules's two answers (21 Oct 2026, asked in this chat)

1. **Delete = the trash.** A note or folder goes to `.trash/` in the notes folder, keeping its
   path there, as Obsidian does: restorable in the app and in Finder, travels with a backup.
   Empty trash (behind a Confirm) is the only permanent delete.
2. **A rename takes its links with it**, exact forms only: `[[Old]]`, `[[folder/Old]]`,
   `[[Old.md]]`, `[[Old|label]]`, `[[Old#heading]]`, `[[Old#^block]]`, in the body and in front
   matter, never inside code; the dialog says first "2 notes link here; their links will follow."

## Inventory rows closed (§7 and the first "Two facts")
| Thing | Change | Now how |
|---|---|---|
| note | rename | Note ⋯ → Rename…, or the tree row's ⋯. File, `title:` line and exact links follow; Undo in the toast |
| note | move | Note ⋯ → Move to… (folder picker), the tree row's ⋯, or drag onto a folder (desktop); links by path follow |
| note | delete | Move to the trash (note ⋯ or tree ⋯), Undo in the toast; Trash view: Restore, Empty trash |
| folder | create (empty) | The tree header's folder button (phone: the tree sheet's header), or a folder's ⋯ → New folder here |
| folder | rename, move, delete | A folder's ⋯ → Rename… / Move to… / Move to the trash (Confirm says how many notes go), or drag |
| history | see, restore | Note ⋯ → History: versions newest first, diff against now, Restore this version (a normal save, so Undo and History can step back) |

The first "Two facts" row is closed for notes and folders only; people, companies and projects
get the same actions in waves 2 and 3 through `noteActions.ts` (below).

## How wave 2 (1D, 1F) and 1E use `noteActions.ts`
```ts
import { renameNote, moveNote, trashNoteWithUndo, sayMoved, restoreFromTrash, linkersOf, linkersSentence } from "../noteActions.js";
import { RenameNoteDialog, MoveDialog, trashFolderRequest } from "../notes/actions.js";

// Rename a person, a company, a project note: the dialog does it all (links follow, toast + Undo).
{renaming && <RenameNoteDialog note={{ id, path }} onDone={(moved) => navigate(addressFor(moved.path))} onClose={() => setRenaming(false)} />}

// Or without the dialog (a name field of your own): one call, then the toast.
const done = await renameNote(path, "New name");      // throws ApiError: show it under your field
sayMoved(`Renamed to “New name”.`, path, done, (back) => reload(back));

// Put a note in the trash with Undo in the toast; leave the page in `after`.
await trashNoteWithUndo(path, title, { after: () => navigate({ kind: "people" }), restored: (id) => id && navigate(...) });

// Move to a folder with the picker (folders from listFolders()).
{moving && <MoveDialog item={{ kind: "note", id, path, title }} folders={folders} onDone={...} onClose={...} />}
```
- `renameNote` / `moveNote` send `links: true` by default; pass `{ links: false }` only to move
  the file alone. The server answers `{ id, path, links, notes }`.
- Every function is one request and throws the server's refusal (`failureText` makes it a
  sentence). A page that keeps a NoteSync for the note should `await sync.flush()` before and
  `sync.refresh()` after (Notes does this in `settleOpen` / `afterChange`).
- Before saving a rename, `linkersOf(noteId, newPath)` + `linkersSentence` gives the line to show.

## Not done (and why) / needs Jules
- **Folder-bound projects** (a `projects` row of kind `folder`, key = the folder's path; the seed's
  "Team Ops" = `Shared`) lose their folder when it is renamed, moved or trashed: the row keeps the
  old path. 1E owns projects; it should carry the row along (or refuse) in `moveFolder`.
- **A trashed project note** leaves its registration row (the owners' then, CLAUDE.md "Projects
  are bound by tag"); 1E's "delete a project" should call `trashNote` and decide about its files.
- Front matter that names a note in plain text (`company: Northwind`, not `[[Northwind]]`) does
  not follow a rename: 1F, when it renames a company, should rewrite those with
  `updateFrontmatter` (or write the relation as a link).
- Markdown links (`[text](Old.md)`) never follow; the dialog counts them as "won't follow".
- No Ask Orr or MCP tool for trash, move or history (stage 1 rule 4: don't add AI tools).
- Tree drag is desktop only (HTML drag and drop); on a phone, Move to… does it.
- `.trash` restore of a whole folder is per item (each note and file has Restore); there is no
  "restore folder" button.
- Bugs seen elsewhere, not fixed: `VaultStore.write` accepts any other dot path (`.claude/x.md`)
  and indexes it until the next restart, when the walk drops it again.
