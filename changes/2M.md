### Where the MCP server lives, and why that path holds

Claude is told `command: <app>/node` (the app's own Node: `Contents/MacOS/node` in the .app,
`node.exe` beside `orrama-desktop.exe` in `%LOCALAPPDATA%\Orrama`) and `args: [<resources>/server/mcp.mjs]`
(`Contents/Resources/server/mcp.mjs`, `%LOCALAPPDATA%\Orrama\server\mcp.mjs`). Updates (the updater,
or a new installer) replace the app in place, so these paths stay. A Mac app moved to another
folder is followed at its next start (`refreshClaude`). An app run where it was downloaded (App
Translocation) or from the disk image is refused with "Move Orrama to your Applications folder…",
since that path goes away.

## Token decision (Jules, 18 Nov, question tool)

**Orrama's private file** (recommended, chosen): the token lives only in `<data>/claude/connection.json`
(owner-only), read by the MCP server at every call. Claude Desktop's settings and the Claude Code
command name the file (`ORRAMA_CONNECTION`) and never hold the token, so the command is safe to
copy and show, and a new port or token needs nothing rewritten in Claude. Not chosen: Credential
Manager on Windows (the MCP server would need a new native module or PowerShell at each start to
read it), and the token in Claude's config env (it would sit in Claude's file and in a command
people paste into a terminal).
