## The switch-over (for the integrator, with Jules's OK)

The live app reads `BASALT_*` from four places outside the repo. One trap decides the order:
**`pnpm ship` only kills the agent, and launchd restarts it with the environment it loaded**,
not the plist on disk. Renaming the plist and then shipping would restart the new code on the
old names, which it refuses: a crash loop. So the switch is in two phases, and phase add is
harmless to the old build:

- **Phase add**: `ORRAMA_X` with the same value beside every `BASALT_X`. Old code reads
  `BASALT_X`; new code reads `ORRAMA_X` and is satisfied because the twin exists.
- **Phase drop**, once the new build is confirmed: remove each `BASALT_X` whose twin holds the
  same value.

`changes/R13-switchover.py` does both. Dry run unless `--apply`; prints variable names, never
values; backs each file up to `~/.orrama-switchover-backup/<time>-<phase>-<pid>/` (700/600)
and refuses to overwrite a backup; writes atomically keeping the file's mode; reads back and
compares. `--only plist|claude-json|vault-mcp|launch` does one file; `--vault-mcp` is required
for the vault's `.mcp.json`; `--home` runs it on copies. Tried on copies (fake secrets: none
printed, values carried, plutil OK, backups 700/600, a second run changes nothing) and as a dry
run on the real files.
