# F4: Four small fixes before the rename

## Built
- Job 1, CI red on Linux: already fixed on the base by 412ee4b (the ſ test expects the
  stamped id where the volume does not fold ſ); CI green on ubuntu, macOS and Windows since.
  Checked here, no new commit: on a case-sensitive APFS disk image (does not fold ſ) the test
  before 412ee4b fails exactly as CI did and passes after (9 passed, 4 skipped); on APFS 13/13.
- Job 2, the store stops scheduling at close (commit 70b19e6). The real cause was leaked
  watchers: `server.test.ts` calls `store.load()` again on its live store, each load started a
  new chokidar watcher over the old one, and only the newest was closed. `load()` now closes
  the watcher it replaces; `close()` sets `closing` so no settle timer or new folder's second
  look is set, and clears timers again after the watcher closes.
- Job 3, note names every disk holds (commit 3f8a07f): `unportableName` moves to
  `apps/server/src/portableName.ts` (uploads.ts re-exports it); `VaultStore.write` judges a
  creation (file name and any folder it makes), `VaultStore.move` a changed file name and any
  folder it makes. Refused on every platform; existing names never judged (Jules, 14 Oct).
- Job 4, Remove says when they're still mentioned (commit 2c7e7ed): `inText` on each project
  person (server, same resolver as the panel); the Confirm adds "They are still mentioned
  elsewhere in the project note, so they stay listed."

## Changelog lines (user-facing, for [Unreleased] → Changed / Added / Fixed / Removed)
- Changed: a new note, or a note moved to a new name, must have a name every disk can hold:
  no `" * : < > ? |`, no trailing dot or space, no Windows device name (CON, NUL, COM1…). The
  New note dialog says why. Notes that already have such a name keep working.
- Changed: on a project's page, removing someone who is also linked in the note's text says
  that they stay listed, and why.
- Internal: the vault store schedules nothing once it starts closing, and re-loading it closes
  the watcher it replaces (no more "The database connection is not open" after a test run).
