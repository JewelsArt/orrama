## Built
- The desktop notices and the crate licence guard: `scripts/desktop-notices.mjs` writes
  `THIRD_PARTY_NOTICES_DESKTOP.txt` (Node's LICENSE from the pinned archive; every Rust crate compiled
  into the window for the target, normal dependencies only, with the licence files it ships, identical
  texts printed once; a crate with no file gets its SPDX text from `apps/desktop/licences/`) into
  `resources/server/` and its `web/`. `apps/desktop/crate-licences.json` (every crate in Cargo.lock, all
  platforms, 482) is held by `apps/web/src/crateLicences.test.ts` to `ALLOWED_LICENCES`, which gains
  `Unicode-3.0` (ICU, under Tauri's URL parser; FSF-compatible); the SPDX reader now minds brackets
  (`(MIT OR Apache-2.0) AND Unicode-3.0` was misread). `prepare-bundle` runs it; NOTICE names the file.
- Settings' foot: under "Source code", "Third-party notices: web app, server" (+ ", desktop app" when
  `/api/health` has a launch id, i.e. the app's own server). Links, no new page.
- Bundle config: `app` + `dmg` + `nsis`, macOS 13.5+ (Node 24's own minimum: its binary says `minos
  13.5`), ad-hoc (`signingIdentity: "-"`), `hardenedRuntime: false`, NSIS per user, English, WebView2
  download bootstrapper, `licenseFile` = LICENSE, publisher, category, short description.
  `[profile.release]`: one codegen unit, LTO, `opt-level = "s"`, stripped.
- `scripts/release-build.mjs` (`pnpm --dir apps/desktop release:mac`): licence guards → web app built
  into `node_modules/.cache/orrama-release/web` (never `apps/web/dist`; `package-server --web <dir>` is
  new) → fetch-node → package-server → notices → `tauri build --bundles app,dmg` / `nsis`. Plain Node, no
  shell, the same on the Windows runner.
- `scripts/install-check.mjs`: `--app` (a .app or install folder) or `--installer` (Windows: `/S` into a
  temp folder, check, `uninstall.exe /S`, notes folder still there). The check: Node + server + LICENSE,
  NOTICE and the three notices in place; the installed Node runs the installed server with the
  contract's environment on empty temp folders and its own home; `/api/health` answers with the launch
  id; the desktop notices are served; stdin closed → exit 0, no WAL.
- `.github/workflows/release.yml` (new), `desktop.yml` (now Windows), `scripts/release-version.mjs`,
  `ci-workflow.test.ts` pins them. Dockerfile on `node:24-slim` (wave 1 leftover).

## Measured on this Mac (M-series, 24 GB, nothing else building)
- **`release:mac`: 1.4 min** with a warm `target/` (licence guards 1 s, web 3 s, Node/bundle/notices
  2 s, `tauri build` 77 s), max RSS 1.8 GB. A clean release `cargo build`: 39 s with the default
  profile, **74 s with the size profile** (1.5 → 1.8 GB RSS).
- **Shell binary 10.3 MB → 4.5 MB** with `[profile.release]` (−56 %).
- **`Orrama_0.1.0_aarch64.dmg`: 45.0 MB.** The .app: 144 MB (Node 117 MB of it, re-signed 121.8 MB;
  shell 4.3 MB; `server/` 22.2 MB + notices 0.6 MB ×2).
- `THIRD_PARTY_NOTICES_DESKTOP.txt`: 0.6 MB for the Mac (238 crates; Node's LICENSE ~0.12 MB).
- `codesign -dv Orrama.app`: `Identifier=com.orrama.desktop`, `flags=0x2(adhoc)`, `Signature=adhoc`,
  `TeamIdentifier=not set`, sealed resources (214 files). `Contents/MacOS/node`: re-signed by Tauri,
  `flags=0x2(adhoc)`, no hardened runtime (Node's OpenJS signature is replaced on the Mac: Tauri signs
  every sidecar; on Windows node.exe is untouched). `codesign --verify --deep --strict`: valid.
- `spctl -a -vv`: **`rejected`** for the .app, `rejected, source=no usable signature` for the .dmg. A
  friend sees "Apple could not verify 'Orrama' is free of malware…", Done; then System Settings →
  Privacy & Security → "Orrama was blocked…" → **Open Anyway**, password, Open. Once per install.
- Info.plist: `NSHumanReadableCopyright` = "Copyright © 2026 Jules Timothy Sekelj. Licensed under the
  GNU AGPL v3 or later.", `LSMinimumSystemVersion` 13.5, `com.orrama.desktop`, productivity category.

## What still needs Windows, and how to prove it
Nothing has run on Windows yet. **After the Actions reset (~1 Nov), the integrator, once `main` is pushed:**

```bash
gh workflow run release.yml --ref main -f version=0.1.0
gh workflow run desktop.yml --ref main
```

**Green for `release.yml`** (windows job, ~20 min, ~40 billed minutes): "build the installer" ends with
`Orrama 0.1.0 for x86_64-pc-windows-msvc: …/nsis/Orrama_0.1.0_x64-setup.exe (≈40–50 MB)`; "Node's
signature" prints `Valid: CN=OpenJS Foundation…`; "install, run, stop, uninstall" prints "installed into …", the
four check lines, "uninstalled", "the notes folder is still there" and "Install check passed."; a **draft** release `v0.1.0-test.<run>` holds
`Orrama_0.1.0_x64-setup.exe`. A tag `v0.1.0` exists on an old commit: test builds by hand use their own
draft tag, never that one. Delete test drafts when done; never publish them. **Green for
`desktop.yml`**: clippy clean on the cfg(windows) code, `cargo test --lib` 33 passed with Node on PATH
(the supervisor test runs, not "no node on PATH: skipped"). The Mac dmg for a draft: `pnpm --dir
apps/desktop release:mac` here, then `gh release upload <tag> <dmg>`.

Likely first-run failures and where to look: `tauri build` fetching NSIS / the WebView2 bootstrapper
(network on the runner); `release-build` refusing because `crate-licences.json` is stale (after 2C adds
a crate: run `node scripts/desktop-notices.mjs --licences` + the guard, commit); NSIS `/D=` with a
space-free temp path (it is); the uninstaller returning before it finishes (the check waits up to 2 min
for `Orrama.exe` to go).

**Jules's Windows checklist** (UTM with Windows 11 ARM, ~6 GB RAM, nothing else running; or a friend's PC;
x64 Orrama runs emulated on ARM):
1. In the VM's browser, signed in to GitHub (the repo is private), download `Orrama_0.1.0_x64-setup.exe`
   from the draft release. (Downloading in the browser keeps the "from the internet" mark that makes
   SmartScreen speak; a file copied in from the Mac would not.)
2. Open it: "Windows protected your PC" → **More info → Run anyway**. If nothing offers Run anyway,
   Smart App Control is on (Windows Security → App & browser control → Smart App Control): note it,
   that PC waits for the Store build.
3. Installer: no admin (UAC) prompt; the licence page shows the AGPL **in paragraphs** (one long line
   = the LF line endings need converting, tell me); Install; Finish with "Run Orrama".
4. "Starting Orrama…", then the door. Time it. No console window appears for node.exe.
5. First run: an account, **Start empty** → Explorer: `C:\Users\<you>\Orrama` holds `Orrama\What things
   are.md`; make a note, it appears there.
6. `%LOCALAPPDATA%\com.orrama.desktop\` holds `basalt.db`, `desktop.json`, `logs\server.log`, and **no**
   `secrets.json`; Credential Manager → Windows Credentials lists `server secrets.com.orrama.desktop`.
7. Settings (foot): Source code, and Third-party notices → web app, server, desktop app: each opens in
   the browser, not the window.
8. Start menu → Orrama again: the window comes forward; Task Manager shows one node.exe.
9. End node.exe in Task Manager: "Starting Orrama…", then back.
10. Close the window: node.exe goes; `server.log` ends with "stdin closed: closing"; no `basalt.db-wal`.
11. Reopen: still signed in, the note there. End `Orrama.exe` in Task Manager: node.exe gone within
    seconds.
12. A document's Download lands in Downloads; Sign in with ChatGPT opens the browser.
13. Settings → Apps → Orrama → Uninstall, leaving "Delete the application data" **unticked**:
    `C:\Users\<you>\Orrama` is still there, `%LOCALAPPDATA%\Orrama` is gone.
14. Install again, open: the same account signs in, the notes are there.
15. Delete the Credential Manager entry, open Orrama: "Orrama can't read its key", nothing started.
