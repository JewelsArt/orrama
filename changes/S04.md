## Changelog lines (user-facing, for [Unreleased] → Fixed / Security / Internal)
Fixed
- Fixing a note's capitalisation in Obsidian or Finder no longer makes Basalt undo the rename and rewrite the note over and over; the note keeps its id and its bytes.
- A path that differs from an existing note only in letter case or Unicode form now means that note: a save to it edits it instead of replacing it.
- New note, New contact and New company no longer replace a note that already exists at that path; they say where it is. Names with `:` or quotes no longer break the note's front matter.
- Uploading a payslip, a statement or a project document whose name is already used keeps both files (`payslip (2).pdf`); a payslip refused as already filed is not stored.
- Opening a document named with a curly apostrophe, an en dash or a macOS screenshot's narrow space no longer stops the server.
- Notes in a folder linked into the vault from elsewhere are there after a restart, not only after their next edit.
- Markdown links written relative to their note (`[up](../Up.md)`) and links to names stored decomposed (`Résumé`) resolve in the map, backlinks and the note's links.
- A project tagged `project/my_thesis` (an underscore, another script) opens. Two projects whose notes share a title stay two projects. A note that only mentions `#project/x` in its text no longer adds its tasks to x, and the board and the project's page count the same tasks.

Security
- A folder editor could overwrite an `#only/<team>` note, or a note in a subfolder whose grant excludes them, by changing one letter of its path's case (ACL-001). Writes now resolve to the note on disk and are judged by it; folder grants compare case- and Unicode-insensitively.

Upgrading
- Project names now come from the project note's `title:` (unchanged when it has none). On the live vault three cards are renamed: Basalt → "Basalt — team knowledge tool", School Resits → "School Resits — June/July 2026", Graduation Internship → "Graduation Internship Search".

Internal
- `PUT /api/vault/note` takes `create: true` (409 when a note is at the path in any spelling). Both upload routes answer with the name the file was stored under.

## CLAUDE.md changes to apply (exact text, and where)
1. **Permission model, rule 6**: append after "Never derive a folder from an unresolved path.":
   > The path is also spelled the way the disk spells it: `resolvePath` maps each segment to the entry the directory holds, exact first, then case- and NFC-insensitively (`apps/server/src/diskPath.ts`), so on APFS `shared/eng secret.md` IS `Shared/Eng Secret.md` — that note, its `#only` tags and its folder's grant, merged into, never replaced by a new file. Folder grants compare folded too (`foldPath`, acl.ts). The watcher believes a spelling only when the directory lists it exactly (`listedExactly`): `existsSync` says yes to every spelling of a file, and trusting it turned a case-only rename in Obsidian into an endless restamp loop (audit STO-012).
2. **Conventions & gotchas**, after the "Files in the vault are replaced, never rewritten in place" bullet, a new bullet:
   > **A create never replaces.** `PUT /api/vault/note` with `create: true` answers 409 when a note is at the path in any spelling; every New … flow sends it (`apps/web/src/newNote.ts`) — without it PUT is an upsert. Uploads go through `storeUpload` (`apps/server/src/uploads.ts`): the same bytes are that file, a different file with a used name becomes `name (2).ext`, and the answer names the file stored. `writeFileAtomic(…, { exclusive: true })` links instead of renaming, so a file that appeared since the check is not lost. Files are served under their own name with `contentDisposition` (same file): an ASCII fallback plus RFC 5987 `filename*` — a raw name above U+00FF in a header throws outside every handler and stops the process.
3. **One shared vault with Obsidian**, append to the first paragraph:
   > A folder linked in from elsewhere (a symlink to a synced folder) is part of the vault: followed at boot, by the watcher and for writes, as Obsidian follows it. A link back into the vault, or up its own tree, is only a second name for notes that have one and is left out everywhere; a write through one is a 400 (`linksIntoVault`, diskPath.ts). One file is one note: a second name for a file the index holds under a name that still exists is not indexed.
4. **Projects are bound by tag, not by folder**, replace the paragraph with:
   > A note joins a project through a `project/<slug>` tag in its **front matter**; an inline `#project/x` in the body binds nothing. Folder location is irrelevant: a note under `04-Projects/thesis/` with only a `thesis` tag is indexed, searchable and visible in Documents, but does not belong to the Graduation Thesis project. There is one slug grammar, `PROJECT_SLUG_RE` / `projectSlugOf` in core `vault.ts` (a letter or digit of any script, then letters, marks, digits, `_` and `-`, at most 64 — one path segment), used by registration, the board and every route; a nested tag (`project/thesis/2026`) is no project. `projects` rows in SQLite are keyed on that tag (`kind='tag'`, `key='project/thesis'`), and every surface tells projects apart by key (`projectKeyOf`, `progress` keyed by key): a name is display only, and two projects may share one. A project is named by its project note's `title:` (`projectName(projectNoteFor(…))`), else by the name it was registered under — never by whichever tagged note was indexed first. Project progress counts checkbox tasks inside tagged notes, so tagging a checklist-heavy note changes the project's totals.
5. **Design rules**, in the paragraph on why a Basalt graph looks sparser, after "(with or without `.md`, `%20`-decoded).":
   > A markdown link is tried relative to its own note first (`[up](../Up.md)`, Obsidian's "Relative path to file"; `VaultIndex.resolveLinkOf`), a wiki link never is; keys fold case and Unicode normalisation (NFC), so `[[Résumé]]` finds a name macOS stored decomposed.

## Not fixed (and why) / needs Jules
- Decisions taken with Jules (11 Oct): one path identity = the spelling on disk (case- and NFC-insensitive match, exact first); project names = the project note's `title:`, else the registered name.
- STO-010: `lookAgainLater` (the second look at a brand-new folder) still takes real directories only, so a folder linked inside a folder created in the same instant waits for its next event. No test here can pin that race, so the hunk was not kept.
- INP-001: the ticket's defence in depth (a try/catch around stream replies) is not added; the only caller-controlled header on those replies is now built by one helper.
- COR-016, other instances of the class in other sessions' files, each a one-line `resolveLink(l.target)` → `resolveLinkOf(note, l)`: the workspace people panel and the people picker's duplicate check (routes/projects.ts:292 and :477, S05), the agent's open-note context (routes/ai.ts:101, S07), typed facts (core graph.ts:191) and related-note suggestions (core related.ts:36).
- COR-004: `store.projects()` names a project from its project note even when the caller cannot read that note (it feeds tasks' `project` field) — the same exposure the frozen row name had (ACL-004 class, S12).
- ACL-005 class: a create-only 409 confirms that a path is taken (the message names it only when the caller can read the note). Unavoidable for a create; S12's ticket.
- Test environment, not code: the full `pnpm test` runs every server test file in parallel and, with several other sessions' dev servers up, macOS refuses new FSEvents watchers (`EMFILE … watch`), failing whichever watcher tests lose the race — the untouched baseline fails the same way. With Jules's OK I stopped six stale, childless `tsx watch` processes (from the deleted KG and R0 worktrees, and one 4-day-old dev watcher in ~/basalt; never the live app). Server suites here were run with `--maxWorkers=3`.
