## Board vs app: differences left on purpose

- **Reply all** is not there: `/api/mail/message` sends no Cc, so a Reply all would quietly drop everyone copied. It needs Cc from the server (see below).
- **The preview after the subject** in a row ("· Thanks for the draft…") is left out: the inbox endpoint sends no snippet.
- **"Written from your note Research plan"** on a draft and the **"In Orrama:" chips** under a message are left out: nothing records which note a draft came from, or what a message is about.
- **The relation line's typed part** ("supervises Graduation thesis") comes from the knowledge graph. Jules's live vault has no ontology note yet, so there it reads only "Thesis supervisor at Westerdok".
- **The draft card shows the recipient's address** as well as their name: the agent chose it, so it is always visible before Send.
- **All has no unread count**, as on the board (the old list had one).
- **On the phone** the account, Check now and Write sit in a row under the top bar: the shell's top bar has only Find, where the board draws Write. Back is the shell's chevron (the board says "‹ Primary"), and Forward stays visible (the board hides it on the phone, which would lose it there).
- **Block images** is in the ··· menu (the board shows no images bar). While images are blocked, a quiet line above the message says so with Show images.
- **Discard on a draft row** in the list appears at the row's end under the pointer (always on the phone); the board shows only Review.
- **The composer has no board.** It is built from the system's Field, Input, Textarea, draft bar and buttons, in the reading pane's box.
- **Orr's Write pose while drafting** is not shown: Mail can't know when he is drafting (that happens in Ask, R12).
- **People's slugs** (`/people/ines-vermaat`) use the file name, lower-cased and hyphenated (`entitySlug`, `mail/people.ts`). R9/R11 own the rule; swap in theirs when it lands.
