2. **"## Conventions & gotchas"**, replace the bullet "**An Ask run stops with its request**" with:
   > - **An Ask run stops with its request** (`routes/ai.ts`): the response closing early (the panel's Stop, closing the panel, leaving the page) aborts the run, so no later model call or tool call happens; `BASALT_AI_TIMEOUT_MS` (120 s) bounds it and the digest, which also makes one attempt. A run stopped mid-answer errors the SDK's stream, and `pipeUIMessageStreamToResponse` rethrows that from a promise nobody awaits — Node ends the process on it — so the route pipes a stream that ends itself instead (`agent-abort-midstream.test.ts`). **Logged errors carry no bodies**: `errSerializer` (logging.ts) drops `requestBodyValues`, `responseBody`, `errors`, `lastError` and the like — the AI SDK's errors hold the whole prompt.
3. **"## The agent's model"**, add a paragraph at the end:
   > Ask Orr (`AskPanel.tsx`) sends the note the page is about as `contextNoteId` (`ask/targets.ts`) and draws each tool call as a sentence (`ask/working.ts`): a new agent tool gets a case there, or it reads "Used <name>". Earlier questions live on the device (`basalt-ask-history`, the open one in sessionStorage `basalt-ask-open`), slimmed to names, ids and counts: note text, excerpts and mail bodies are never copied into the browser.

## Board vs app: differences left on purpose
- **Keycaps**: the board draws ⌘J beside the title and "↵ ask · ⇧↵ new line" under the field. CLAUDE.md's design rules say no keycaps on screen, so ⌘J is in the Close and rail tooltips and Enter / Shift-Enter are not drawn.
- **"Everything he reads stays on this server."** is not true with a hosted model, so the line says who reads it: "What he reads goes to Anthropic / Google / OpenAI / the model you set up to answer." Jules may want other words.
- **Orr's proposal box under an answer** ("Add 1 and 3 to the agenda I drafted for Friday? Add both · Not now"): the agent returns text and tool calls, nothing the panel could turn into those buttons. Not built; he can ask it in words.
- **Board's steps** ("Read his latest mail", "Looked at Friday in Planning") assume tools the agent doesn't have (no calendar-read tool); the panel says the tools there are.
- **Empty panel**: no board draws it. A short line on what he reads and does, and "He reads <note> with your question." when the page is about a note.
- **Capture and New** have no board of their own; both are the system's Dialog (bottom sheet on the phone).
- On the phone the panel steps aside when you follow a link from it (the panel is the screen); on the desktop it stays.
