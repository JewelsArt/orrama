# S05 — Tasks and sections: address by id, write only your section

## Fixed
- COR-001 — task edits name the task by block id or text; a line is only a hint, a bare line is a 400, a stale or gone task a 409 (commit 805b822)
- WEB-004 — the side panel's tasks reload after your own saves; a tick sends the task's identity (commit 805b822)
- COR-009 — a block id copied onto a second line stays with the first; the copy is its own task and gets its own id when promoted (commit 805b822)

## Changelog lines (user-facing, for [Unreleased] → Fixed / Security / Internal)
- Fixed: ticking, blocking, re-dating, scheduling or booking a task after the note changed elsewhere (an Obsidian edit, a decision logged above it) could change a different task. Every task edit now names the task by its block id or its text, and is refused when that task is no longer there.
- Fixed: the side panel of an open note showed its tasks as they were when the note opened, so ticking one after typing above it ticked its neighbour. The panel now follows your saves.
- Fixed: a promoted task line copied in Obsidian (with its `^t-` id) made both lines one task. The copy is now a task of its own and gets its own id when it is scheduled or promoted.
- Fixed: saving "Edit goals" without changing anything turned checkbox goals into plain bullets, flattened sub-items and bulletised prose. The editor now opens on the section's own text.
- Fixed: logging a decision, capturing a thought or linking a person collapsed blank lines everywhere in the project note, code blocks included.
- Fixed: the project page read and wrote a `### Goals` (or Decisions, People) nested in another section, and missed `## Goals ##`, adding a second heading.
- Fixed: linking a person whose name matched another note's filename linked that note instead; the person never appeared, each click added another line, and Remove could not delete it.
- Fixed: renaming a box on the Documents board and switching tab straight away lost the rename.
- Fixed: typing a year into a project's start or deadline wrote every half-typed year (0002, 0020, 0202) into the note.
- Internal: `POST /api/tasks/{check,status,dates,promote,schedule,blocks}` take `text` and refuse a request naming neither `blockId` nor `text` (400); the agent's and MCP's task tools take `text` too.

## CLAUDE.md changes to apply (exact text, and where)
- In "Conventions & gotchas", after the bullet **A task's status is its checkbox** (…), add:
  - **A task is named, not pointed at.** Every task edit — `/api/tasks/check`, `/status`, `/dates`, `/promote`, `/schedule`, `/blocks`, the agent's and MCP's task tools — says which task by its `blockId`, or by its `text` (the display text or the raw line) with the line it was seen on as a hint. `locateTask` (`packages/core/src/tasks.ts`) reads the note with the index's own parser and returns the task or null: a block id never falls back to the line, a line alone names nothing (the schemas answer 400), and a text that matches no task or several is a 409. The note moves under a client — an Obsidian edit, a decision appended above — and an edit by line ticked whatever task slid into place. A `^t-` id copied onto a second line belongs to the first; the copy is a task of its own until promoting gives it its own id.
- In "The project workspace is the note", after the paragraph starting **None of it is a database row.**, add:
  - A slot is a `##` heading (a closed `## Goals ##` too; a `### Goals` inside another section is not it), and writing one replaces its body between its first and last non-blank line and no other byte (`sections.ts`). Goals are edited as source: `GET /api/projects/:slug` sends `goalsSource`, the section as the note has it, and the editor saves that; `goals` is display items only and is never written back. The people picker writes `[[<path>|<title>]]`, because a bare `[[title]]` resolves to any note with that filename first.
