## Jules's answers (23 Oct 2026, asked in this chat; all three as recommended)

1. **Rename changes only the name.** The title (`title:`, and a first `# Heading` that said the
   old name) follows; the key (the `project/<slug>` tag on every note, `04-Projects/<slug>.md`,
   the `files/` folder, `documents.canvas`, the address) stays.
2. **Delete: notes elsewhere stay and lose the project.** The project's note, the notes in
   `04-Projects/<slug>/` and its files go to the trash; notes tagged into it that live elsewhere
   keep their place and text and only lose the `project/<slug>` tag. The Confirm names both
   lists. Restoring from the trash brings the project back; it does not re-tag those notes (the
   toast's Undo does).
3. **Hidden projects come back from a "Removed from the board" shelf** beside Paused,
   Cancelled and Done (owners), each row with Put back. Remove keeps meaning "this isn't a
   project", Archive "finished". The flag stays database-only. Jules's live app has 6 such rows
   (deadlines, week-plan, zzz-scratch, a demo, city-map, paris-budget): they will show on the
   shelf.

## Changelog lines (user-facing, for [Unreleased])
- Added: A project can be renamed from its title (or ⋯ → Rename…) and deleted from ⋯ → Delete
  the project…: the Confirm says which notes and documents go to the trash and which notes stay
  and leave the project; Undo in the toast, or Notes → Trash, brings it back.

  can become a step. Goals are added one line at a time.

  off again. A document can be renamed (its extension stays) and put in the trash, from the
  list or from the board.

  archive a project; the row's status is a menu.
- Changed: Deleting a project document moves it to the trash instead of deleting it for good.
- Changed: A new project's first step sits under "Tasks", where new steps go.
- Changed: A second project with a name already used gets its own key instead of joining the
  first one; names in any alphabet keep their letters in the address.
- Removed: Suggested links on a project's documents board (nothing suggested them).
- Fixed: Clearing a project's start or deadline left `start: ""` in the note.
- Fixed: The window title of a project page showed its address in words, not its name.
- Fixed: A project note put in the trash left an empty project on the owners' board.
- Fixed: Renaming a folder cut a folder-based project off from it.

## Board vs app: differences left on purpose
- No board for these controls; they reuse Menu, Dialog, Confirm, Row, SearchField, toast, 1C's
  trash and the project page's row-with-⋯ pattern (now `MenuRow` in ProjectOverview.tsx).
- Rename is in place on the title, with ⋯ → Rename… opening the same field (a hidden affordance
  needs a visible way in). One field, two ways to open it.
- Removing a line asks first (a Confirm quoting it); taking a note off the project and trashing a
  file don't ask but offer Undo, like 1C's trash.
